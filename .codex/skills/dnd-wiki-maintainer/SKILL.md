# D&D Wiki 維護

將此專案視為可追溯的規則編譯庫。所有回應與新增內容使用繁體中文（台灣）。

## 開始前

1. 讀取根目錄 `AGENTS.md`，它優先於本 skill。
2. 依任務路由讀取指定章節：
   ```powershell
   npm.cmd run policy:show -- "章節名稱"
   ```
3. 先檢查最近一層索引與工作目錄狀態；不要覆蓋與任務無關的既有變更。
4. 僅讀取 `原始資料/`。不要修改、重新命名或刪除其中檔案。

## 維護流程

### Wiki 內容與來源

- 先以 `附件/翻譯詞彙表.md` 核對專有名詞；必要時使用 `npm.cmd run glossary:lookup` 與 `npm.cmd run source:find`。
- 新增、重建或大幅改寫條目前，完整讀取對應的 `模板/`。
- 為每個規則主張保留可定位來源，並維持 Frontmatter、版本、來源權威性、`confidence`、索引與雙向連結一致。
- 新詞沒有可定位中文來源時，依治理規範建立待確認譯名；不要臆造翻譯。

### 索引、連結與 Obsidian 圖譜

- 使用中文目標檔名或允許的中文相對路徑建立 Wiki 連結。
- 表格內的帶別名連結必須跳脫管道符號：`[[目標\|顯示名稱]]`。
- 不要讓模板留下可被 Obsidian 解析的占位 Wiki 連結；占位語法必須跳脫為純文字。
- 不要建立空白頁以消除斷鏈。報告語意不明的目標，等待人類決定。
- 更新或移動條目時，同步維護所屬索引與反向連結。

### 驗證

- 一般變更後執行 `npm.cmd run lint`。
- 使用者要求全庫檢查或合併前驗證時，執行 `npm.cmd run lint:all`。
- 純 Markdown 表格修正時，另檢查標頭分隔列、欄位數、未跳脫管道符號與表格前空白列。
- 回報結果時區分錯誤、警告與資訊；清楚列出未修正且需人類決定的項目。

## Git 與 GitHub

- 只有在使用者明確要求時，才執行 commit、push、分支刪除、合併或 PR 操作。
- 提交前先檢查範圍與工作目錄狀態；不要納入暫存物、依賴目錄或無關檔案。
- 使用單一邏輯批次的提交訊息：`類型(範圍): 簡短摘要`。
